# Modern Minify

Минификация CSS, JavaScript и HTML, отложенная загрузка скриптов и обработка
Google Fonts — без Composer, без внешних зависимостей и без логов.

Версия 0.2.0. Требуется WordPress 7.0+, PHP 8.0+. Лицензия GPL-2.0-or-later.

## Статус: этап 2 — конвейер страницы

Плагин переписывает HTML обычной страницы: минифицирует разметку, инлайн-блоки
и локальные файлы, переносит хешированные копии в кеш, расставляет `async` /
`defer` и по желанию переносит скрипты в подвал. Административных экранов ещё
нет: настройки меняются через `MMF_Config::update()`, счётчики и предупреждения
видны в админке как уведомления.

Переписывание — самая опасная часть плагина, поэтому все правила ниже
сформулированы как «что остаётся без изменений», а любая ошибка обработки
одного тега оставляет этот тег ровно таким, каким его напечатала тема.

### Что работает в 0.2.0

| Что | Как |
|---|---|
| Точка входа | буфер вывода только для обычной HTML-страницы; не админка, не REST/AJAX, не cron, не фиды, не sitemap, не JSON/XML, не предпросмотр |
| HTML | удаляются обычные комментарии и пробелы между блоками; текст не склеивается |
| Защищённые блоки | `<pre>`, `<textarea>`, `<code>`, `<svg>`, `<script>`, `<style>`, `<title>`, `<template>`, `<noscript>` копируются побайтово |
| Комментарии | сохраняются условные (`<!--[if`), блоки редактора (`<!-- wp:`), метки цикла (`<!--more-->`, `<!--nextpage-->`, `<!--noteaser-->`) |
| Скрипты | локальные `<script src>` минифицируются в кеш, `src` заменяется; внешние домены не трогаются |
| Стили | локальные `<link rel="stylesheet">` минифицируются в кеш, `href` заменяется; инлайн `<style>` минифицируется |
| `integrity` / `crossorigin` | удаляются только у переписанных тегов: браузер отверг бы изменённый файл по старому хешу |
| `async` | по списку шаблонов `async_js` |
| `defer` | общий переключатель `defer_js`, кроме `async`, `jquery` и списка `defer_skip` |
| `type="module"` | не переписывается, не минифицируется, `async`/`defer` не получает |
| Подвал | `move_scripts_to_footer` переносит локальные `<script src>` из `<head>` в конец `<body>` с сохранением порядка |
| Инлайн CSS | `inline_css` заменяет небольшой файл на `<style>` (порог `inline_css_limit`, по умолчанию 20 КиБ) |
| print-стили | `remove_print_css` удаляет `<link media="print">` |
| Счётчики | опция `mmf_stats` для будущего экрана статуса |
| Конфликты | при активном втором минификаторе плагин не обрабатывает страницы и сообщает об этом в админке |
| Объединение | настройки есть, но объединение файлов в этом этапе не выполняется; при включённом флаге в админке показывается предупреждение про HTTP/2 |

## Как выбирается страница

Буфер ставится на `template_redirect` (приоритет 1) и снимается самим PHP.
Обрабатывается только то, что похоже на целую HTML-страницу: если в ответе нет
`<!doctype>` / `<html` / `<body>`, если заголовок `Content-Type` не `text/html`
или если страница была отдана кусками (промежуточный сброс буфера), не
обрабатывается ничего. Документ обрабатывается ровно один раз за запрос.

Аварийные выключатели для отладки: `?mmf_no_minify=1` и короткий `?mmf_off=1`.

## Правила безопасности вывода

1. Тег, который не удалось разобрать, остаётся исходным; остальные теги
   обрабатываются дальше.
2. Если минификатор вернул исходник (не смог сжать, битый файл, файл не похож
   на код), замена `src`/`href` не делается вообще.
3. `src`/`href` заменяется только когда файл кеша действительно существует:
   каталог только для чтения не должен давать 404 на каждой странице.
4. Путь файла получается из URL, приводится `realpath()` и проверяется на
   принадлежность каталогу WordPress; читаются только `.js` и `.css` до 2 МиБ.
5. В конце проверяется, что из документа не пропали doctype, `</html>`,
   `</body>` и больше 20% тегов; иначе отдаётся исходный HTML.
6. Никаких записей в лог: счётчики и предупреждения — в админке.

## Настройки

Все значения живут в одном массиве `mmf_settings`; читаются только через
`MMF_Config::get()`, поэтому дефолты и типы применяются в одном месте.

| Ключ | Тип | По умолчанию | Что задаёт |
|---|---|---|---|
| `enabled` | bool | `false` | главный выключатель: выключенный плагин ничего не трогает |
| `minify_js` | bool | `true` | минифицировать JavaScript |
| `minify_css` | bool | `true` | минифицировать CSS |
| `minify_html` | bool | `true` | минифицировать HTML |
| `merge_js` | bool | `false` | объединять JS-файлы (предупреждение в админке) |
| `merge_css` | bool | `false` | объединять CSS-файлы (предупреждение в админке) |
| `inline_css` | bool | `false` | встраивать небольшие CSS-файлы в страницу |
| `inline_css_limit` | int, 0…5120 | `20` | порог встраивания, КиБ; `0` отключает встраивание |
| `remove_print_css` | bool | `false` | убирать стили `media="print"` |
| `async_js` | список | `[]` | шаблоны URL, которым ставится `async` |
| `defer_js` | bool | `false` | ставить `defer` всем локальным скриптам, кроме исключений |
| `defer_skip` | список | `[]` | минифицировать, но не откладывать |
| `move_scripts_to_footer` | bool | `false` | перенести локальные `<script src>` из `<head>` в конец `<body>` |
| `exclude_js` | список | `[]` | файлы и теги, которые не обрабатываются вообще |
| `exclude_css` | список | `[]` | то же для CSS |
| `disable_when_logged_in` | bool | `false` | не обрабатывать страницы авторизованных |
| `remove_meta` | bool | `false` | убирать лишние `meta`-теги (этап 5) |
| `remove_emoji` | bool | `false` | убирать emoji-скрипты (этап 5) |
| `fonts_method` | `inherit` \| `inline` \| `async` \| `exclude` | `inherit` | что делать с Google Fonts (этап 3) |
| `fonts_swap` | bool | `true` | добавлять `display=swap` |
| `fonts_local` | bool | `false` | отдавать шрифты локально |
| `fonts_disable` | bool | `false` | не обрабатывать шрифты |
| `cache_ttl` | int, 0…3650 | `30` | срок жизни файлов кеша в днях; `0` — не удалять по возрасту |
| `debug` | bool | `false` | режим отладки для экрана статуса |

Списки принимают и массив, и строку: элементы разделяются переводом строки или
запятой, пустые и повторяющиеся отбрасываются, порядок сохраняется.

### Шаблоны путей

`async_js`, `defer_skip`, `exclude_js` и `exclude_css` сравниваются с URL файла
без учёта регистра. Поддерживаются две формы:

| Шаблон | Что означает |
|---|---|
| `jquery` | подстрока: URL содержит `jquery` |
| `/plugins/foo/` | подстрока: путь содержит этот каталог |
| `*jquery*` | `*` — любое количество символов: совпадение в любом месте URL |
| `*/plugins/foo/*` | путь целиком: каталог `/plugins/foo/` и что угодно до и после |
| `https://example.test/*` | все файлы этого хоста |

Шаблон с `*` проверяется против всего URL и против его пути, поэтому
`/wp-content/plugins/foo/*` работает без схемы и хоста. Исключение (`exclude_*`)
означает «не трогать совсем»: ни минификации, ни замены URL, ни `async`/`defer`.
`defer_skip` — точечнее: файл минифицируется, но не откладывается.

Экрана настроек в 0.2.0 нет: значения пишутся через `MMF_Config::update()`.
Опция уже зарегистрирована в Settings API (`register_setting( 'mmf',
'mmf_settings' )` на `admin_init`), поэтому сохранение из будущей формы
автоматически проходит через `sanitize()`.

## Кеш

- Каталог: `wp-content/uploads/mmf/` текущего сайта.
- Имя файла: `md5( исходник + отпечаток настроек + версия плагина )` плюс
  `.min.js` или `.min.css`. Одинаковый вход даёт одинаковое имя, изменённая
  настройка или новая версия плагина — новое имя вместо устаревшего файла.
- Заглушка `index.php` (листинг каталога закрыт), `.htaccess` нет: файлы должны
  отдаваться браузеру.
- Уборка: `wp_schedule_event( …, 'daily', 'mmf_cache_cleanup' )`, удаляются файлы
  старше `cache_ttl`. `0` в TTL означает «хранить до ручной очистки».
- Полная очистка — `MMF_Cache::delete_all()`; каталог при этом остаётся.
  `uninstall.php` удаляет и его.

## Счётчики

Опция `mmf_stats` (не автозагружаемая) хранит накопительные числа: `pages`,
`files`, `inline`, `async`, `defer`, `moved`, `print`, `failed` и `updated`.
Запись выполняется не чаще раза в минуту, чтобы плагин не делал `UPDATE` на
каждый просмотр страницы: числа нужны экрану статуса как порядок величины, а не
как аудит.

## Второй минификатор и объединение

Если активен другой плагин, который тоже минифицирует страницу, двойная
минификация ломает CSS и JS. Плагин определяет такую ситуацию по каталогам
активных плагинов (список можно расширить фильтром `mmf_conflicting_plugins`),
не обрабатывает страницы и показывает в админке сообщение об ошибке. Имя
второго плагина в тексте не называется.

При включённом `merge_js` / `merge_css` показывается предупреждение: на HTTP/2
объединение обычно замедляет сайт, потому что браузер загружает файлы
параллельно. Флаги не блокируются — это осознанный выбор владельца сайта.

## Инлайн-блоки

Инлайн `<script>` и `<style>` минифицируются, но инлайн-скрипт **никогда** не
получает `async`/`defer`: отложенный инлайн-блок выполнился бы после разметки,
которая рассчитывает на его переменные. Для загрузчика следующего этапа
зафиксирован порог: блок длиннее 200 000 символов не откладывается никогда
(`MMF_Assets::can_defer_inline()`), потому что обёртка большого блока — это
регулярное выражение по нему.

## Библиотеки

Сторонний код лежит в `lib/` обычными файлами, с лицензиями рядом. Composer,
`vendor/` и PSR-4-автозагрузка не используются: каждый файл подключается через
`require_once` под `class_exists()`, поэтому уже загруженная другим плагином
копия не объявляется второй раз.

| Каталог | Библиотека | Версия | Лицензия |
|---|---|---|---|
| `lib/jsmin/` | [mrclay/jsmin-php](https://github.com/mrclay/jsmin-php) | 2.4.3 | MIT |
| `lib/minify-css/` | [matthiasmullie/minify](https://github.com/matthiasmullie/minify) | 1.3.76 | MIT |
| `lib/minify-css/path-converter/` | [matthiasmullie/path-converter](https://github.com/matthiasmullie/path-converter) | 1.1.3 | MIT |

Правки в скопированных файлах — guard `ABSPATH` в начале (чтобы файл нельзя
было вызвать напрямую) и несколько помеченных pragma анализатора на ложные
срабатывания; подробности — в `lib/README.md`.

## API

```php
MMF_Config::all();                 // все настройки с дефолтами
MMF_Config::get( 'minify_css' );   // одна настройка
MMF_Config::is_enabled();          // главный выключатель
MMF_Config::update( array( 'minify_js' => false ) );

MMF_Minifier::minify_js( $js );    // исходник при любой ошибке
MMF_Minifier::minify_css( $css );  // то же для CSS
MMF_Minifier::hash( $js, 'js' );   // имя кеша для исходника
MMF_Minifier::stats();             // счётчики: js, css, cached, failed

MMF_Cache::hash( $source, 'css' ); // имя кеша
MMF_Cache::put( $hash, $minified, 'css' );
MMF_Cache::get( $hash, 'css' );
MMF_Cache::url( $hash, 'css' );
MMF_Cache::delete_all();
MMF_Cache::stats();                // файлы, размер, дата обновления

MMF_HTML::minify( $html );         // разметка без защищённых блоков
MMF_Assets::rewrite( $html, $settings );       // ['html' => …, 'stats' => …]
MMF_Assets::can_defer_inline( $js );           // порог 200 000 символов
MMF_Stats::all();                  // накопительные счётчики
MMF_Conflicts::is_active();        // активен ли второй минификатор
```

## Что дальше

Порядок этапов зафиксирован карточками:

1. **0.3.0** — экраны в «Настройках» (`options-general.php`), тестовый режим
   только для администраторов, ссылка-переключатель в админ-баре, автосброс
   кеша при обновлении плагинов/темы/ядра и при сохранении настроек, отдельный
   выключатель минификации инлайн-блоков, Google Fonts с локальной отдачей и
   Font Awesome.
2. **0.4.0** — Delay JS: скрипты держатся как `type="text/plain"` до первого
   взаимодействия (scroll, mousemove, touchstart, keydown, click, wheel) или до
   таймера 5 секунд, затем восстанавливаются в исходном порядке.
3. **0.4.1** — `?ver=` в трёх режимах (хеш по умолчанию, удаление, сохранение;
   у внешних файлов параметр удаляется) и удаление emoji-скриптов, включённое
   по умолчанию. Заодно убираются `<meta name="generator">` и generator-тег в
   RSS: версия ядра в URL и в мета-тегах подсказывает атакующему мишень.
   `readme.html` не наше дело.

Не планируется: удаление неиспользуемого CSS и critical CSS, ленивая загрузка
картинок и iframe, предзагрузка/prefetch, CDN и кеш страниц, менеджер ассетов
по записям.
