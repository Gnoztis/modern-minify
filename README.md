# Modern Minify

Минификация CSS, JavaScript и HTML, отложенная загрузка скриптов и обработка
Google Fonts — без Composer, без внешних зависимостей и без логов.

Версия 0.6.5. Требуется WordPress 7.0+, PHP 8.0+. Лицензия GPL-2.0-or-later.

## Статус: 0.6.5 — честный список встроенных исключений

Плагин переписывает HTML обычной страницы, владелец управляет этим из
«Настройки → Modern Minify». Активный плагин сразу работает: отдельного
выключателя нет, поведение задают опции. Скрипты можно отложить до первого
действия посетителя или до разбора DOM, внешние CDN-файлы по умолчанию
скачиваются в кеш, шрифты Google Fonts локализуются и печатаются инлайном, а
граватары заменяются локальной заглушкой.

### Что работает в 0.6.5

| Что | Как |
|---|---|
| Экран настроек | «Настройки → Modern Minify», шесть вкладок, сохранение через Settings API; свой CSS/JS инлайном и только на этом экране |
| Точка входа | буфер вывода только для обычной HTML-страницы; не админка, не REST/AJAX, не cron, не фиды, не sitemap, не JSON/XML, не предпросмотр |
| HTML | удаляются обычные комментарии и пробелы между блоками; текст не склеивается |

| Комментарии | сохраняются условные (`<!--[if`), блоки редактора (`<!-- wp:`), метки цикла (`<!--more-->`, `<!--nextpage-->`, `<!--noteaser-->`) |

| print-стили | `remove_print_css` удаляет `<link media="print">` |
| Тестовый режим | оптимизация только для `manage_options`; в админ-баре видно пометкой |
| Аварийные выключатели | `?mmf_off=1` и `?mmf_no_minify=1`; ссылка-переключатель в админ-баре |
| Шрифты | Google Fonts: по умолчанию скачать и отдать локально, либо `display=swap`, либо не обрабатывать; Font Awesome: не обрабатывать / встроить CSS |
| Кеш | не чистится при обновлении плагина, смене темы или сохранении настроек: имена файлов содержат хеш, старые доживают TTL, и страницы из кеша не запрашивают удалённые файлы |
| Граватары | по умолчанию локальная inline-SVG заглушка: ни одного запроса к `secure.gravatar.com` |
| Счётчики | опция `mmf_stats`, видны на вкладке «Статус» |
| Скрытие версий | `?ver=` → хеш содержимого (по умолчанию), удаление или без изменений; у внешних файлов параметр удаляется |
| Generator | удаляется `meta name="generator"` и generator-тег RSS |
| Emoji | emoji-скрипт и стили ядра убраны по умолчанию (админка не затрагивается) |
| Delay JS | скрипты из списка не загружаются до первого действия посетителя; инлайн-загрузчик, общий для двух режимов |
| Внешние файлы | по умолчанию скачиваются в кеш и отдаются со своего домена; API-скрипты, привязанные к домену, остаются внешними и видны в статусе |
| Встроенные исключения | один массив `MMF_External::BUILTIN` (хост → причина): интерфейс и движок читают его, расхождения невозможны; в списке актуальные ЮMoney/ЮKassa, Т-Банк, QIWI, Stripe, PayPal, карты и капчи |
| CSS шрифтов | локализованный CSS Google Fonts печатается инлайном; больше 50 КБ — отдаётся файлом |
| Рекомендуемые настройки | кнопка и вопрос-подсказка на «Статусе» применяют безопасный профиль; у полей профиля — бейдж «Рекомендуется» |

| Сброс кеша | очищает и статистику: счётчики обнуляются, размер и число файлов читаются с диска |
| Диагностика | только таблицы и счётчики; таблицы не шире своей карточки и не прижаты к правому краю |
| Список скриптов | на «Статусе»: имя, режим (обычный/defer/async/отложен/инлайн/Rocket) и позиция последней учтённой страницы |
| jQuery Migrate | по умолчанию снимается на фронтенде, админка не затрагивается |
| Rocket-режим | весь JavaScript, включая инлайн, выполняется после разбора DOM в исходном порядке; выключен по умолчанию |
| Объединение | рядом стоящие локальные CSS/JS собираются в пакет; выключено по умолчанию, отказ при любой ошибке |
| defer для внешних | отдельный переключатель, только `defer`, никогда `async`; выключен по умолчанию |

## Экран настроек

Пункт меню — в разделе «Настройки» (`options-general.php`), верхнего пункта нет.
Своего `<h1>` у страницы нет: заголовок уже печатает WordPress.

Вкладки: «Статус», «JavaScript», «CSS», «Шрифты», «Внешние файлы», «Настройки», «Дополнительно».
Форма одна: неактивные вкладки скрыты через `display:none`, но остаются в
разметке, поэтому сохраняются все поля сразу, а не только открытой вкладки.
Неотмеченный чекбокс отправляет скрытый `0` — иначе поле отсутствовало бы в
запросе и санитайзер вернул бы значение по умолчанию.

- **Статус**: «плагин активен», карточка «Последнее действие», чипы функций по
  группам (включённые и выключенные различаются точкой и текстом, не только
  цветом), четыре группы счётчиков в две колонки (страницы и файлы, отложенная
  загрузка, внешние файлы, кеш и ошибки), каталог и размер кеша, сброс кеша
  (он же обнуляет статистику) и рекомендуемые настройки.
- **Внешние файлы**: режим, встроенные исключения таблицей с причиной
  (не редактируются), свои исключения с добавлением и удалением строк, предел
  размера и список хостов последней учтённой страницы — таблица внутри карточки,
  колонки 60/40, статус бейджем сразу после адреса; ниже 900px строка
  складывается в два уровня. Диагностика в интерфейсе — только таблицы и числа,
  копируемых текстовых полей нет.
- **Дополнительно**: TTL, лимиты объединения, тестовый режим и отладка.
- У полей, входящих в рекомендуемый профиль, стоит бейдж «Рекомендуется»; если
  значение отличается — бейдж называет рекомендуемое («Рекомендуется: включить»).
  Профиль — единственный источник: бейджи, кнопка и подсказка читают одно место.
- Логические поля: чекбокс и пояснение в одну строку; ниже 900px пояснение
  переносится под чекбокс.
- Сохранение идёт через Settings API (`settings_fields( 'mmf' )` → `options.php`),
  опция уже зарегистрирована с `sanitize_callback` из `MMF_Config`.
- Кнопка «Сбросить кеш» — GET-ссылка с nonce и проверкой `manage_options`.
- Собственные CSS и JS страницы подключаются через `wp_add_inline_style` /
  `wp_add_inline_script` и только на этом экране: функция подключения первой
  строкой сверяет `$hook_suffix`.
- Счётчики и размер кеша читаются только на этом экране, а не на каждой
  странице админки.

## Уведомления

Подтверждения действий (сброс кеша, рекомендуемые настройки, переключение
тестового режима) — тосты в правом верхнем углу под админ-баром, поверх
контента: страница не сдвигается. Успех закрывается сам через 8 секунд, пауза —
при наведении и фокусе внутри, закрытие — по Esc и кнопкой. Ошибки не
закрываются сами никогда. После перезагрузки тост показывается один раз:
флаг в URL несёт nonce, а JS убирает его из адресной строки, поэтому F5 не
дублирует сообщение. Анимация отключается при `prefers-reduced-motion`.

Тост — не единственное место: результат действия остаётся в карточке
«Последнее действие» на «Статусе», а ошибки дублируются постоянным блоком, а не
только всплывающим сообщением. Встроенные уведомления WordPress (`.notice`) не
затрагиваются.

## Тестовый режим и выключатели

- **Тестовый режим** (`test_mode`): конвейер работает только для пользователей с
  `manage_options`. В админ-баре видно состояние, на экране — уведомление.
- **`?mmf_off=1`** (и длинная форма `?mmf_no_minify=1`) отдаёт страницу без
  обработки любому посетителю.
- В админ-баре один пункт «Modern Minify» с подпунктами: «Настройки»,
  «Выключить/включить на этой странице», «Тестовый режим: вкл/выкл» (переключатель
  с nonce).

## Как выбирается страница

Буфер ставится на `template_redirect` (приоритет 1) и снимается самим PHP.
Обрабатывается только то, что похоже на целую HTML-страницу: если в ответе нет
`<!doctype>` / `<html` / `<body>`, если заголовок `Content-Type` не `text/html`
или если страница была отдана кусками (промежуточный сброс буфера), не
обрабатывается ничего. Документ обрабатывается ровно один раз за запрос.

## Правила безопасности вывода

1. Тег, который не удалось разобрать, остаётся исходным; остальные теги
   обрабатываются дальше.
2. Если минификатор вернул исходник (не смог сжать, битый файл, файл не похож
   на код), замена `src`/`href` не делается вообще.
3. `src`/`href` заменяется только когда файл кеша действительно существует.
4. Путь файла получается из URL, приводится `realpath()` и проверяется на
   принадлежность каталогу WordPress; читаются только `.js` и `.css` до 2 МиБ.
5. В конце проверяется, что из документа не пропали doctype, `</html>`,
   `</body>` и больше 20% тегов; иначе отдаётся исходный HTML.
6. Никаких записей в лог: счётчики и предупреждения — в админке.

## Настройки

Все значения живут в одном массиве `mmf_settings`; читаются только через
`MMF_Config::get()`, поэтому дефолты и типы применяются в одном месте.
Схема опции — 9.

| Ключ | Тип | По умолчанию | Что задаёт |
|---|---|---|---|
| `enabled` | bool | `false` | главный выключатель: выключенный плагин ничего не трогает |
| `disable_gravatar` | bool | `true` | заменить граватары локальной inline-SVG заглушкой |
| `minify_css` | bool | `true` | минифицировать CSS |
| `minify_html` | bool | `true` | минифицировать HTML |
| `minify_inline` | bool | `true` | минифицировать содержимое `<script>` и `<style>` в самой странице |
| `merge_js` | bool | `false` | объединять рядом стоящие локальные JS-файлы |
| `merge_css` | bool | `false` | объединять рядом стоящие локальные CSS-файлы |
| `merge_max_files` | int, 2…50 | `10` | максимум файлов в одном пакете |
| `merge_max_size` | int, 1…20 | `1` | максимум размера пакета, МиБ |
| `inline_css` | bool | `false` | встраивать небольшие CSS-файлы в страницу |
| `inline_css_limit` | int, 0…5120 | `20` | порог встраивания, КиБ; `0` отключает встраивание |
| `remove_print_css` | bool | `false` | убирать стили `media="print"` |
| `async_js` | список | `[]` | шаблоны URL, которым ставится `async` |
| `defer_js` | bool | `false` | `defer` всем скриптам сразу; если хоть один исключён — никому |
| `remove_jquery_migrate` | bool | `true` | снимать jQuery Migrate на фронтенде |
| `defer_skip` | список | `[]` | минифицировать, но не откладывать |
| `defer_external` | bool | `false` | ставить `defer` внешним скриптам (никогда `async`) |
| `move_scripts_to_footer` | bool | `false` | перенести локальные `<script src>` из `<head>` в конец `<body>` |
| `delay_js` | список | `[]` | шаблоны URL, чью загрузку отложить до первого действия |
| `delay_js_exclude` | список | `[]` | исключения для Delay JS |
| `delay_js_timeout` | int, 1…30 | `5` | страховочный таймаут в секундах |
| `external_mode` | `local` \| `keep` \| `remove` | `local` | что делать с внешними файлами |
| `external_max_size` | int, 1…20 | `2` | предел размера скачиваемого файла, МиБ |
| `external_exclude` | список | `[]` | хосты и части URL, которые остаются внешними |
| `rocket_mode` | bool | `false` | отложить весь JavaScript до `DOMContentLoaded` |
| `rocket_exclude` | список | `[]` | пути и `id`, которые Rocket-режим не трогает |
| `exclude_js` | список | `[]` | файлы и теги, которые не обрабатываются вообще |
| `exclude_css` | список | `[]` | то же для CSS |
| `disable_when_logged_in` | bool | `false` | не обрабатывать страницы авторизованных |
| `remove_generator` | bool | `true` | убирать версию WordPress из `<head>` и из RSS |
| `remove_emoji` | bool | `true` | убирать emoji-скрипт и стили ядра на страницах сайта |
| `ver_mode` | `hash` \| `remove` \| `keep` | `hash` | что делать с `?ver=` в URL своих CSS/JS |
| `fonts_method` | `off` \| `swap` \| `local` | `local` | что делать с Google Fonts |
| `fawesome_method` | `off` \| `inline` | `off` | что делать с Font Awesome |
| `inline_fonts_css` | bool | `true` | печатать локализованный CSS шрифтов инлайном (≤ 50 КБ) |
| `test_mode` | bool | `false` | оптимизация только для администраторов |
| `cache_ttl` | int, 0…3650 | `30` | срок жизни файлов кеша в днях; `0` — не удалять по возрасту |
| `debug` | bool | `false` | режим отладки для экрана статуса |

Списки принимают и массив, и строку: элементы разделяются переводом строки или
запятой, пустые и повторяющиеся отбрасываются, порядок сохраняется.

### Шаблоны путей

`async_js`, `defer_skip`, `exclude_js` и `exclude_css` сравниваются с URL файла
без учёта регистра. Поддерживаются две формы:

| Шаблон | Что означает |
|---|---|
| `jquery` | подстрока: URL содержит `jquery` |
| `/plugins/foo/` | подстрока: путь содержит этот каталог |
| `*jquery*` | `*` — любое количество символов: совпадение в любом месте URL |
| `*/plugins/foo/*` | путь целиком: каталог `/plugins/foo/` и что угодно до и после |
| `https://example.test/*` | все файлы этого хоста |

Шаблон с `*` проверяется против всего URL и против его пути, поэтому
`/wp-content/plugins/foo/*` работает без схемы и хоста. Исключение (`exclude_*`)
означает «не трогать совсем»: ни минификации, ни замены URL, ни `async`/`defer`.
`defer_skip` — точечнее: файл минифицируется, но не откладывается.

## Шрифты

**Google Fonts** (`fonts_method`, по умолчанию `local`):

- `off` — ссылка остаётся ровно такой, какой её напечатала тема;
- `swap` — к URL добавляется `display=swap`; уже существующий `display` не
  переопределяется;
- `local` — плагин скачивает CSS и файлы шрифтов в кеш, переписывает `@font-face`
  на локальные адреса и печатает локализованный CSS прямо в страницу через
  `<style>` (`inline_fonts_css`, включено по умолчанию). Если CSS больше 50 КБ,
  он отдаётся файлом `*.fonts.css`, чтобы не раздувать HTML; такие случаи видны
  в счётчике «CSS шрифтов отдано файлом». Заодно убираются
  `preconnect`/`dns-prefetch` к шрифтовым CDN: они больше не нужны.
  Скачанное живёт в общем кеше и удаляется по TTL или кнопкой сброса.
  Если тема предзагружает шрифт через `<link rel="preload" as="font">`, этот
  `href` переписывается на тот же локальный адрес — иначе браузер предзагружал бы
  один файл, а использовал другой.

Скачивать разрешено только хосты из списка (шрифтовые CDN и CDN Font Awesome),
только по HTTPS, с таймаутом 5 секунд и ограничением размера (256 КиБ на CSS,
1.5 МиБ на файл шрифта, не больше 24 файлов на таблицу стилей). Любая ошибка —
сеть, код ответа, пустое тело, слишком большой файл — оставляет исходную
ссылку: страница с внешним шрифтом лучше страницы со сломанным.

**Font Awesome** (`fawesome_method`): `inline` скачивает таблицу стилей и
заменяет `<link>` на `<style>` с содержимым; относительные `url(...)` внутри CSS
становятся абсолютными, чтобы файлы шрифтов продолжали находиться. `off`
оставляет ссылку как есть.

### Относительные URL в стилях

Любой `<link rel="stylesheet">`, который плагин переносит в кеш (или встраивает
в страницу), сначала пересчитывается: каждое относительное `url(../fonts/x.woff2)`
становится абсолютным адресом от **исходного каталога таблицы стилей**, а не от
кеша. Иначе браузер искал бы шрифт в `uploads/mmf/../fonts/` и получал 404 —
ровно этот баг был в 0.6.0. Правила:

- абсолютный URL, который уже указывает на существующий локальный файл, не
  трогается: то, что работает, не «чиним»;
- `url(...?v=1#iefix)` сохраняет и query, и фрагмент;
- у локализованной внешней таблицы стилей относительные адреса считаются от её
  собственного домена, поэтому шрифт остаётся на CDN (или уходит в кеш, если
  скачан), но никогда не превращается в `uploads/fonts/...`;
- в одном `src` может быть несколько форматов (`woff2`, `woff`, `ttf`) — каждый
  `url()` обрабатывается отдельно, отсутствующий вариант не превращается в
  мёртвую ссылку.

## Граватары

`disable_gravatar` (по умолчанию **включено**) заменяет аватар на встроенную
SVG-заглушку через `data:`-URI: ни одного запроса к `secure.gravatar.com`, IP
посетителя и хеш его адреса никуда не уходят. Перехвачены
`pre_get_avatar_data`, `get_avatar` и `get_avatar_url` — тема не сможет обойти
замену, даже если строит URL сама. Админка и cron не затрагиваются, поэтому
диагностика плагина и письма остаются как были. Счётчик «Аватаров заменено» —
на вкладке «Статус».

## Скрытие версий

Версия WordPress в исходном коде страницы — это карта применимых к сайту
уязвимостей, поэтому по умолчанию она не видна ни в URL, ни в `<head>`, ни в
ленте.

### `?ver=` (`ver_mode`)

| Режим | Что делает | Цена |
|---|---|---|
| `hash` (по умолчанию) | `?ver=7.1.5` → `?v=8f3a1c`: короткий хеш содержимого файла | файл читается один раз на страницу; кеш браузера сбрасывается при изменении файла |
| `remove` | параметр `ver` удаляется полностью | после обновления браузер может держать старый файл до конца кеша (CSS/JS отдаются на 7 дней) |
| `keep` | URL не меняется | версия остаётся в коде страницы |

Правила:

- трогается только URL, в котором действительно есть `ver`: адреса без него не
  переписываются;
- остальные параметры сохраняются, `ver` и прежний `v` заменяются одним
  значением (повторный прогон фильтра ничего не ломает);
- **внешний файл** (CDN, чужой домен) нельзя прочитать, поэтому хеш для него не
  строится: параметр удаляется, как в режиме `remove`;
- админка не затрагивается: там `ver` нужен для отладки и своего кеша.

### Generator и emoji

- `<meta name="generator">` удаляется (`wp_generator`), тег `generator` в RSS
  отдаётся пустым (`the_generator`). Оба — только на сайте, админка не
  затрагивается.
- Emoji-скрипт и стили ядра снимаются на страницах сайта
  (`print_emoji_detection_script`, `print_emoji_styles`,
  `wp_enqueue_emoji_styles`), а фильтры `the_content_feed`, `comment_text_rss` и
  `wp_mail` убираются всегда: это не админский интерфейс, а лишний код на каждой
  странице.
- `readme.html` в корне сайта плагин не трогает: его лучше закрыть на сервере
  (правило в конфигурации веб-сервера), это не задача плагина.

## Rocket-режим

Откладывает **весь** JavaScript страницы до окончания разбора DOM и выполняет
его в исходном порядке, включая инлайн-блоки между внешними файлами. Это не
Delay JS: там ждут первого действия посетителя и только файлы из шаблонов, здесь
страница разгружается целиком и сразу после готовности документа. Режим
выключен по умолчанию.

- Внешний тег становится `<script type="text/plain" data-mmf-rsrc="…">`,
  инлайн — `<script type="text/plain" data-mmf-rcode="1">` с прежним
  содержимым. Ничего не загружается и не выполняется до `DOMContentLoaded`.
- Загрузчик (инлайн, меньше 3 КБ, печатается один раз в конце `<body>`)
  выполняет очередь **по одному скрипту**: внешний файл дожидается `load` или
  `error`, только потом создаётся следующий. Поэтому порядок сохраняется, а
  ошибка одного файла не останавливает очередь.
- Инлайн-блок вставляется как обычный `<script>` в свою позицию — `var` и
  `function` из него видны следующим скриптам так же, как при обычной загрузке.
- Локализация внешних файлов и минификация работают до переписывания: в
  плейсхолдере оказывается уже локальный URL.
- Никаких внешних запросов: загрузчик только инлайн.

Не переписываются:

- инлайн-блоки с `document.write`/`document.writeln` — после разбора DOM это
  стирает страницу;
- `type="module"` — у модулей своя семантика загрузки;
- скрипты с `data-mmf-defer="false"` — собственный opt-out темы;
- `id`, начинающиеся с `mmf-`, — сам плагин;
- всё из `rocket_exclude` (пути и `id`, поддерживается `*`);
- не-JavaScript типы (`application/ld+json` и подобные).

Особые случаи: на соединении с `saveData` и в браузере без
`addEventListener`/`Promise` очередь восстанавливается сразу, без ожидания.
Повторный запуск загрузчика ничего не делает.

### CSP

Загрузчик печатается через `wp_get_inline_script_tag()`, поэтому плагин политики
добавляет к нему `nonce`. Если на сайте включён строгий CSP, а nonce к нашему
тегу не пришёл, режим **не включается**: плейсхолдеры без рабочего загрузчика
оставили бы страницу без JavaScript. На вкладке «JavaScript» в этом случае
показана причина и `sha256`-хеш загрузчика — его можно добавить в политику.
Политику, добавленную веб-сервером, плагин не видит; для неё есть фильтр
`mmf_csp_present`.

### Взаимодействие с Delay JS

Rocket-режим откладывает всё, поэтому список Delay JS при нём не действует: если
файл попал в оба, побеждает Rocket-режим. На вкладке «JavaScript» об этом
написано, а в статистике растёт счётчик «Отложено Rocket-режимом».

## defer и порядок скриптов

`defer_js` — режим «всё или ничего». Он применяется, только если **каждый**
внешний скрипт страницы получит `defer`. Если хотя бы один остаётся обычным —
исключение (`defer_skip`, `exclude_js`), уже стоящий `async`, `type="module"`,
внешний домен при выключенном `defer_external`, присутствующий
`jquery-migrate` — `defer` не ставится **никому**, и страница остаётся такой,
какой её напечатала тема.

Причина: `defer`-скрипт выполняется после разбора документа, обычный — во время.
Смешанный режим переставляет зависимости: тема, которая ждёт jQuery, выполняется
раньше библиотеки. Порядок важнее миллисекунд.

Решение видно без консоли:

- на «Статусе» строка «defer на странице»: «применён» или причина отказа
  (какие файлы помешали);
- карточка «Скрипты последней учтённой страницы»: имя, режим и позиция каждого
  скрипта. Если `defer` применён, а в списке есть «обычный», это и есть причина
  ошибки порядка — статус говорит это прямым текстом.

jQuery Migrate по умолчанию снимается на фронтенде (`wp_deregister_script`),
админка не затрагивается. Если владелец вернёт его, скрипт снова считается
зависимостью: он блокирует `defer` на странице, а не локализуется вслепую.

## Delay JS

Файлы, чьи URL совпали с шаблонами `delay_js`, не загружаются и не исполняются,
пока посетитель не начнёт взаимодействовать со страницей. Это отличается от
`async`/`defer`: те всё равно качают файл сразу.

- Вместо `<script src="…">` в разметке остаётся
  `<script type="text/plain" data-mmf-src="…" data-mmf-delay="1"></script>`:
  браузер такой тег не загружает и не исполняет.
- Инлайн-загрузчик (меньше 2 КБ, печатается в страницу один раз) ждёт первое из
  `scroll`, `mousemove`, `touchstart`, `keydown`, `click`, `wheel`, а если
  посетитель ничего не делает — срабатывает таймаут `delay_js_timeout` секунд
  после готовности документа. Страница без действий всё равно получает рабочий
  функционал.
- При срабатывании загрузчик восстанавливает очередь в порядке документа: каждый
  плейсхолдер заменяется скриптом с `async=false`, поэтому браузер исполняет их
  по порядку. Атрибуты (id, data-*) переезжают, `data-mmf-*` не копируются.
- CSP: загрузчик печатается через `wp_get_inline_script_tag()`, поэтому плагин
  политики добавляет к нему `nonce`; загрузчик копирует этот `nonce` на каждый
  восстановленный скрипт.
- На соединении с `navigator.connection.saveData` очередь не откладывается:
  скрипты восстанавливаются сразу, экономя трафик.
- Повторный запуск загрузчика (дубль на странице) ничего не делает — защита от
  двойного исполнения.

Никогда не откладываются:

- `jquery`, `jquery-core`, `jquery-migrate` — от них зависит остальная страница;
- `type="module"`;
- `wp-i18n` и `wp-hooks`: на них держатся переводы и хуки;
- файлы из `exclude_js` и `delay_js_exclude`;
- инлайн-скрипты: это собственный код страницы, в 0.4.0 загрузчик их не трогает.

Отложенный файл не получает `async`/`defer`: временем его загрузки владеет
загрузчик. Список пустой по умолчанию — ничего не откладывается, пока владелец
явно не перечислит шаблоны. В тестовом режиме в админ-баре появляется пометка
«Delay JS активен», а `?mmf_off=1` отдаёт страницу вообще без обработки.

## Объединение файлов

**Честное предупреждение:** на HTTP/2 объединение чаще вредит, чем помогает.
Браузер и так загружает файлы параллельно по одному соединению, а один большой
пакет откладывает первую отрисовку и обновляется целиком при любом изменении.
Включайте, только если измерили: сравните загрузку страницы с объединением и без
(DevTools → Network, «Disable cache»). Поэтому по умолчанию выключено.

Как собирается пакет:

- только **рядом стоящие** локальные теги одного типа, между которыми нет ничего,
  кроме пробелов; каскад и порядок сохраняются;
- CSS-группа — только с одинаковым `media`; `print` и `speech` не объединяются
  никогда;
- JS-группа — только без `async`, `defer`, `type="module"`, `integrity` и
  `crossorigin`; jQuery и его зависимости исключены всегда;
- всё из `exclude_js`/`exclude_css` разрывает группу;
- лимиты: `merge_max_files` файлов и `merge_max_size` МиБ после минификации;
- **отказ закрытый:** любая ошибка чтения, чужой URL, `async`/`module`/`defer` в
  наборе, разный `media`, превышение лимита — и все теги группы остаются на
  месте. Частичный пакет не собирается никогда;
- содержимое — конкатенация минифицированных файлов в порядке разметки, хеш —
  тот же, что у обычных файлов, поэтому смена настроек минификации даёт новый
  пакет и старый кеш не переиспользуется;
- тег пакета помечен `data-mmf-bundle="1"`, и остальной конвейер его не трогает:
  он уже минифицирован, а перенос или `defer` сломали бы порядок, ради которого
  пакет собирался.

### defer для внешних скриптов

`defer_external` (по умолчанию выключен) ставит `defer` внешним `<script src>`,
но никогда `async`. Не трогаются: `type="module"`, скрипты с уже стоящим `async`,
всё из `defer_skip`, `exclude_js` и удалённые режимом `remove`. Чужой код может
зависеть от того, что загрузился раньше остальных, — включайте осознанно и
проверяйте страницу.

На «Статусе» видно, сколько пакетов собрано, сколько файлов в них вошло, сколько
запросов сэкономлено и суммарный размер — по этим числам и решайте, помогает ли
объединение на вашем хостинге.

## Внешние файлы

Внешний запрос отдаёт чужому серверу IP посетителя и Referer, добавляет чужой
домен в `script-src` и заставляет страницу ждать CDN, который может быть
недоступен. Поэтому по умолчанию (`external_mode = local`) внешние скрипты и
таблицы стилей скачиваются один раз, кладутся в кеш и отдаются с сайта; тег
переписывается на локальный URL, а браузер посетителя к чужому домену не
обращается.

Что гарантируется:

- только `https`; только `GET`; таймаут 5 секунд; предел `external_max_size`
  (2 МиБ по умолчанию); редиректы разрешены, но каждая точка перенаправления
  снова проверяется на `https`;
- запросы идут через `wp_safe_remote_get()`, который сам отказывает приватным и
  loopback-хостам — это SSRF-граница;
- проверяются и расширение (`.js`, `.css`), и `Content-Type` ответа: HTML-страница
  ошибки или JSON не будут отданы как скрипт;
- имя файла в кеше — хеш содержимого, TTL и очистка общие с остальным кешем;
- `integrity`/`crossorigin` снимаются **только** с переписанного тега;
- при любой ошибке тег остаётся исходным, а в счётчиках растёт «не удалось
  скачать»; неудача запоминается на 5 минут, а не навсегда, поэтому CDN,
  вернувшийся в строй, снова подхватится;
- повторная страница берёт готовый файл из кеша без сетевого запроса; если файл
  удалён по TTL, будет скачан заново.

Шрифты внутри локализованного CSS не скачиваются: их адреса делаются
абсолютными, чтобы иконки и текст продолжали работать, а в счётчиках
появляется предупреждение о шрифтах — владелец видит, что часть запросов всё
ещё уходит наружу.

### Кого нельзя локализовать

Встроенный список не трогает скрипты, привязанные к домену: их копия сверяет
`Referer` или `Origin` и ломается на чужом адресе. Это карты, капчи, платёжные
виджеты и облачная защита. Два списка: подстроки URL
(`MMF_External::DEFAULT_EXCLUDES`) и доменные суффиксы
(`MMF_External::DEFAULT_DOMAINS`). Суффиксное правило срабатывает на сам домен и
на любой его поддомен, но не на похожий домен: `cleantalk.org` покрывает
`api.cleantalk.org` и `fd-api.cleantalk.org`, а `notcleantalk.org` и
`cleantalk.org.evil.com` локализуются как обычно. Отдельно в списке стоит
`fd-cleantalk.org` — это другой домен сервиса, не поддомен.

Оба списка показаны на вкладке «Дополнительно» таблицей с причиной и
расширяются фильтрами `mmf_external_excluded` / `mmf_external_excluded_domains`
или настройкой `external_exclude`.

Режимы: `keep` — не трогать ничего; `remove` — удалить теги полностью (по
умолчанию выключено, потому что ломает функциональность).

### Что видно владельцу

На вкладке «Статус» — четыре счётчика (локализовано, оставлено, не удалось,
удалено), предупреждения о шрифтах и таблица внешних хостов **последней
учтённой страницы** с пометкой «локализован / оставлен внешним (исключение) /
не удалось скачать». Тот же список выводится в поле для копирования, чтобы его
можно было прислать как диагностику.

## Кеш и TTL

- Каталог: `wp-content/uploads/mmf/` текущего сайта.
- Имя файла: `md5( исходник + отпечаток настроек + версия плагина )` плюс
  `.min.js` или `.min.css`; шрифты — `<hash>.fonts.css` и `font-<hash>.woff2`.
- Заглушка `index.php` (листинг каталога закрыт), `.htaccess` нет: файлы должны
  отдаваться браузеру.
- Уборка: `wp_schedule_event( …, 'daily', 'mmf_cache_cleanup' )`, удаляются файлы
  старше `cache_ttl`. `0` в TTL означает «хранить до ручной очистки».
- **Никакого автосброса при обновлении.** Имя файла содержит хеш содержимого,
  отпечаток настроек и версию плагина, поэтому новая версия или новая настройка
  даёт новые имена, а старые файлы доживают TTL. Удалять их нельзя: страница,
  ещё отданная из кеша nginx или браузера, запросила бы уже удалённый файл и
  получила 404 — именно это ломало локализованные шрифты в 0.6.0.
- Удаляют файлы три пути: ручная кнопка «Сбросить кеш», `uninstall.php` и
  ежедневная уборка по `cache_ttl`.

## Счётчики

Опция `mmf_stats` (не автозагружаемая) хранит накопительные числа: `pages`,
`files`, `inline`, `async`, `defer`, `moved`, `print`, `failed` и `updated`.
Запись выполняется не чаще раза в минуту, чтобы плагин не делал `UPDATE` на
каждый просмотр страницы: числа нужны экрану статуса как порядок величины, а не
как аудит.

## Второй минификатор и объединение

Если активен другой плагин, который тоже минифицирует страницу, двойная
минификация ломает CSS и JS. Плагин определяет такую ситуацию по каталогам
активных плагинов (список можно расширить фильтром `mmf_conflicting_plugins`),
не обрабатывает страницы и показывает сообщение об ошибке на своём экране и в
админке. Имя второго плагина в тексте не называется.

При включённом `merge_js` / `merge_css` на вкладках JavaScript и CSS
показывается предупреждение: на HTTP/2 объединение обычно замедляет сайт,
потому что браузер загружает файлы параллельно. Флаги не блокируются — решает
владелец, по замеру.

## Инлайн-блоки

Инлайн `<script>` и `<style>` минифицируются, но инлайн-скрипт **никогда** не
получает `async`/`defer`: отложенный инлайн-блок выполнился бы после разметки,
которая рассчитывает на его переменные. Для загрузчика следующего этапа
зафиксирован порог: блок длиннее 200 000 символов не откладывается никогда
(`MMF_Assets::can_defer_inline()`), потому что обёртка большого блока — это
регулярное выражение по нему.

Минификация инлайн-блоков отключается отдельным переключателем `minify_inline`:
именно она ломает темы чаще всего, а файловый конвейер при этом можно оставить.

## Переводы

Строки интерфейса — русские, все через `__()`/`esc_html__()` с доменом
`modern-minify`. Каталог лежит в `languages/modern-minify-ru_RU.pot`;
`node tools/scripts/make-pot.mjs modern-minify` обновляет его на месте (файл
`.pot` в `languages/` есть, поэтому генератор не уходит в `lang/`).

## Библиотеки

Сторонний код лежит в `lib/` обычными файлами, с лицензиями рядом. Composer,
`vendor/` и PSR-4-автозагрузка не используются: каждый файл подключается через
`require_once` под `class_exists()`, поэтому уже загруженная другим плагином
копия не объявляется второй раз.

| Каталог | Библиотека | Версия | Лицензия |
|---|---|---|---|
| `lib/jsmin/` | [mrclay/jsmin-php](https://github.com/mrclay/jsmin-php) | 2.4.3 | MIT |
| `lib/minify-css/` | [matthiasmullie/minify](https://github.com/matthiasmullie/minify) | 1.3.76 | MIT |
| `lib/minify-css/path-converter/` | [matthiasmullie/path-converter](https://github.com/matthiasmullie/path-converter) | 1.1.3 | MIT |

Правки в скопированных файлах — guard `ABSPATH` и несколько помеченных pragma
анализатора на ложные срабатывания; подробности — в `lib/README.md`.

## API

```php
MMF_Config::all();                 // все настройки с дефолтами
MMF_Config::get( 'minify_css' );   // одна настройка
MMF_Config::update( array( 'minify_js' => false ) );

MMF_Minifier::minify_js( $js );    // исходник при любой ошибке
MMF_Minifier::minify_css( $css );  // то же для CSS
MMF_Minifier::hash( $js, 'js' );   // имя кеша для исходника
MMF_Minifier::stats();             // счётчики: js, css, cached, failed

MMF_Cache::hash( $source, 'css' ); // имя кеша
MMF_Cache::put( $hash, $minified, 'css' );
MMF_Cache::get( $hash, 'css' );
MMF_Cache::url( $hash, 'css' );
MMF_Cache::write_file( $name, $content );   // шрифты и прочие файлы
MMF_Cache::delete_all();
MMF_Cache::stats();                // файлы, размер, дата обновления

MMF_HTML::minify( $html );         // разметка без защищённых блоков
MMF_Assets::rewrite( $html, $settings );       // ['html' => …, 'stats' => …]
MMF_Assets::can_defer_inline( $js );           // порог 200 000 символов
MMF_Loader::script( MMF_Loader::MODE_INTERACTION, 5000 );  // тело загрузчика
MMF_Loader::script_tag( $js );                 // тег с nonce от CSP-плагина
MMF_Loader::is_hard_excluded( $url );          // jquery, wp-i18n, wp-hooks
MMF_External::process( $tag, $settings );      // внешний тег → локальный
MMF_External::report();                        // хосты последней страницы
MMF_Merge::apply( $html, $settings );           // ['html' => …, 'stats' => …]
MMF_Loader::script( MMF_Loader::MODE_DOMREADY, 5000, MMF_Loader::MAX_BYTES_ROCKET );
MMF_Loader::csp_blocked( $js );                // CSP без nonce → режим выключен
MMF_Loader::hash( $js );                       // sha256 для политики
MMF_Fonts::rewrite_link( $tag, $settings );    // ['tag', 'handled', 'stats']
MMF_Fonts::absolutize_urls( $base, $css );     // относительные url() → абсолютные
MMF_Gravatar::uri();                            // data:image/svg+xml;base64,…
MMF_Version_Hide::filter_src( $url, 'js' );    // ver → хеш / удаление
MMF_Stats::all();                  // накопительные счётчики
MMF_Conflicts::is_active();        // активен ли второй минификатор
```

## Что дальше

Функциональность плана закрыта. Дальше — проверка на живом сайте: тестовый
режим, `?mmf_off=1` и сравнение страниц с оптимизацией и без. Шрифты и
граватары уже включены по умолчанию; пакеты и внешний `defer` включать по
одному, с замером.

### Что изменилось в 0.6.5

- Встроенные исключения сведены к одному массиву `MMF_External::BUILTIN`;
  таблица на вкладке «Внешние файлы» и `host_is_excluded()` используют его, а
  фикстура сверяет набор хостов в интерфейсе с применяемым.
- Обновлены домены: `yoomoney.ru`, `money.yandex.ru`, `money.yandex.net`,
  `yookassa.ru`, `securepay.tinkoff.ru`, `checkout.qiwi.com`, Stripe, PayPal,
  `maps.googleapis.com`, `api-maps.yandex.ru`, капчи. Убраны обрубки
  `money.yandex`, `securepay.tinkoff`, `yookassa`.
- ЮMoney и ЮKassa проверены отдельно: виджет, 3-D Secure и форма-донат остаются
  внешними, похожие домены не задеваются.

### Что изменилось в 0.6.4

- `defer_js` стал «всё или ничего»: смешанный режим больше не переставляет
  jQuery и тему; причина отказа видна на «Статусе».
- На «Статусе» появился список скриптов последней страницы с режимами и
  позициями.
- jQuery Migrate снимается на фронтенде по умолчанию; возвращённый вручную
  блокирует defer.

### Что изменилось в 0.6.2

- `cleantalk.org`, его поддомены и `fd-cleantalk.org` добавлены во встроенные
  исключения по суффиксу домена — с проверкой, что похожие домены не задеваются.
- Локализованный CSS Google Fonts печатается инлайном (`inline_fonts_css`),
  больше 50 КБ — файлом.
- На «Статусе» появилась кнопка «Рекомендуемые настройки»: безопасный профиль с
  подтверждением, сбросом кеша и без изменения исключений и шаблонов.
- Под вкладкой «Настройки» — справка: HTML сжимается в памяти, копии создаются
  только для CSS/JS.

### Что изменилось в 0.6.1

- Мастер-переключатель `enabled` удалён: активный плагин = включённый, а
  управляют опции. Из-за него не срабатывало удаление emoji.
- Относительные `url()` в перенесённых стилях пересчитываются от исходного
  каталога, `?query#fragment` сохраняется, уже абсолютные адреса не трогаются;
  предзагрузки шрифтов переписываются вместе с ними. Это и был 404 на шрифтах.
- Кеш больше не чистится при обновлении плагина, смене темы и сохранении
  настроек — только вручную, при удалении плагина и по TTL.
- Граватары заменяются локальной SVG; шрифты Google Fonts локализуются по
  умолчанию.
- Интерфейс: один пункт в админ-баре с подпунктами, без дублирующего `<h1>`,
  «Состояние» в две колонки, кеш на диске на «Статусе», исключения внешних
  файлов таблицей с причинами.

Не планируется: удаление неиспользуемого CSS и critical CSS, ленивая загрузка
картинок и iframe, предзагрузка/prefetch, CDN и кеш страниц, менеджер ассетов
по записям.
